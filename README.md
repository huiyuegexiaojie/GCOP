# GCOP Studio — 三模式文件混淆工具（钥匙 / 口令 / 混合双因子）

> 把任意文件（文本、PNG、脚本、配置……通吃）变成谁也读不懂的乱码，只有持有钥匙或口令的你能一键还原。
> 扛过两轮 AI 红蓝对抗实测：算法被攻击方完整复原后，强口令容器依然无解。

**零第三方依赖** —— 全部功能只用 Python 标准库实现，`Python 3.10+` 开箱即用，无需 `pip install` 任何东西。

---

## 三种模式

| 模式 | 秘密载体 | 单点泄露后果 | 容器 |
|---|---|---|---|
| 钥匙模式 | 每文件独立随机钥匙文件（参数空间 2⁷⁸~2¹⁷⁶） | 钥匙泄露 = 该文件失守 | `.gcop` + `.gcop.key` |
| 口令模式 | PBKDF2-HMAC-SHA256 ×200k 派生（自包含容器） | 口令泄露 = 同口令文件失守 | `.vx` |
| 混合模式 | 32B 随机种子（钥匙文件）⊕ 口令派生流 | **任一单边泄露均不失守** | `.hx` + `.hx.key` |

工作台支持**结果不落盘**：混淆/解密产物仅存于程序内存，拖出到资源管理器那一刻才写临时文件，关窗即销毁。

## 快速开始

```bash
# 1. 三合一图形工作台（推荐日常使用：拖入文件即可）
python studio/gcop_studio.py

# 2. 命令行混淆 / 还原（钥匙模式）
python gcop.py <file>            # 混淆，生成 <file>.gcop + <file>.gcop.key
python gcop.py <file>.gcop       # 还原（自动寻找同目录钥匙）

# 3. 口令模式 CLI（无任何伴随文件，自包含容器）
python vx.py lock   <file>       # 加密为 <file>.vx
python vx.py unlock <file>.vx    # 输入口令还原
```

Windows 用户可直接双击 `studio/启动工作台.bat`，或把文件拖到脚本图标上。

## 算法概要

核心引擎为**循环轨道置换（Cyclic-Orbit Permutation, GCOP）**：多轮「跨步分组 → 组重排（σ）→ 矩阵转置连续写回 → 组内仿射步进（`Y[r·L+j] = X[σ[r] + g·((a[r]+q[r]·j) mod L)]`）」复合，净置换经 7 项排列不变量与蒙特卡洛零分布检验，与均匀随机不可区分（bigram 存活 Z = 0.4）。

**安全模型（Kerckhoffs 原则）**：算法全公开、可审查，安全性仅依赖秘密本身。
- 口令派生：`PBKDF2(口令, 盐, 200k 轮) + HMAC-SHA256 计数器 DRBG`
- 混合模式：种子流 = `PBKDF2(口令, 盐) ⊕ 随机 32B 种子`，钥匙与口令缺一不可
- v2 加固：自动填充至 16 字节对齐 + 最短 128B + 随机追加 0~2 块，彻底消灭质数长度的仿射退化档位；置换组下限 g ≥ 8

## 红蓝对抗实证

先后由两个独立 AI 当攻击者做对抗测试（黑盒探测 → 运行时逆向 → 独立重实现破解器 → 离线字典 / PIN / GPU 估算）：

- 只有密文、没有口令：**一个字都还原不出来**（参数空间 2⁷⁸ 起步，强口令下等效 2⁹⁸ 工作量）
- 统计检验 7 项全部通过：密文与均匀随机置换不可区分
- 算法被完整复原后，强口令容器（≥80 bit 熵）无一被破
- 弱口令按实测速率阵亡：`qwerty123` 4.4 秒被字典攻破、4 位数字 PIN 98.6 秒被暴力枚举

**这工具的强度等于你的口令强度** —— 请用 4 个随机词或 16 位以上混合字符。
攻击研究工具见 [`research/`](research/)（含攻击方独立实现的通用解密器）。

## 诚实定位

这是**混淆（obfuscation），不是加密（encryption）**：

- 防「拿到文件但没秘密」的翻阅和拿走
- 不防手里已有你原文的人（一对同长度已知明文即可恢复当次参数，但该密钥不可迁移，见下节）
- 文件类型、长度这类指纹会泄露（置换不改变字节多重集）
- 钥匙模式容器无完整性校验

需要对抗已知明文攻击的场合，请用 AES 这类标准加密。

## 一文件一密：恢复出密钥也只适用于当前文件

GCOP 的每次混淆都为当前文件**独立重新随机生成**全套参数（分组宽度 g、组重排 σ、仿射系数 a/q、轮数 rounds），文件与文件之间不存在参数复用；口令模式与混合模式还为每个文件单独随机生成 16 字节盐，即使两个文件用同一个口令，派生出的参数流也不相同。

因此，即使攻击者拿到某文件的明文与密文、完整恢复出这次混淆的全部参数，这份「密钥」也**只对当前这一个文件有效**：

- 换一个文件，参数就是完全不同的随机值，已有分析成果全部作废，必须从头再来
- 破解成本**按文件线性累加**：破一个文件 ≠ 破一类文件，更 ≠ 破这个工具；批量混淆时单点沦陷不会扩散
- 口令模式的例外是**口令本身泄露**（如被字典爆破成功）——攻击者可用口令对任意同口令文件自行派生参数。这是口令便利性的固有代价，混合模式可消除该风险
