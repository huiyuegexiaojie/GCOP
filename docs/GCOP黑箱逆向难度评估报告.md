## 一、黑箱确认的行为特征

| 特征 | 结论 | 依据 |
|---|---|---|
| 变换类型 | 纯字节位置置换 | 密文与原文长度相等（643B）、字节多重集完全一致 |

## 三、劫持场景逆向难度评级

### 场景 A：劫持者只拿到 .gcop（密文Only）—— 逆向难度：极高 ✅
- 信息论层面：纯置换下，所有与密文共享字节多重集的明文**后验等概率**，643B 文本无结构可利用
- 计算层面：穷举 2^5077 不可行；未发现任何统计偏差可供缩小搜索
- 唯一能"验证"的是猜测：若攻击者猜出完整明文，可通过多重集比对立即证实——但对长文本无法穷举猜测

### 场景 B：劫持者还拿到一份同型原文（已知明文）—— 影响有限 ✅
- 可恢复当次置换映射，但每次运行置换独立随机，**已知明文无法迁移**到其他文件
- 部分已知明文只能钉住对应位置，其余位置仍是均匀随机

### 场景 C：劫持者同时拿到 .gcop + .key —— 保护力归零 ❌
- 103B 钥匙即可完整还原。**切勿将 .key 与 .gcop 同渠道分发**

### 场景 D：篡改/完整性 —— 无防护 ❌
- 纯置换无认证机制，密文可被任意重排拼接，还原时不报错

## 五、密钥泄露场景实测（第二阶段）

> 前提修正：作者确认随机种子完全随机（CSPRNG 疑虑排除）。本阶段模拟攻击者同时持有 程序 + .gcop + .key。

### 5.1 关键发现：钥匙是明文 JSON，配方全部暴露

```
{"type": "gcop-key", "version": 1, "n": 115, "g": 23,
 "sigma": [23个元素的组排列], "a": [每组旋转量], "q": [每组仿射步长], "rounds": 24}
```

- `n`=文件长度，`g`=组数（随机），`sigma`=**组级排列**，`a`=组内旋转（0~gs-1），`q`=组内步长（与 gs 互素），`rounds`=轮数
- 密钥尺寸随 g 随机波动（同内容 142B ~ 312B），进一步证实参数逐轮随机
- 密钥本体无任何加密/编码，记事本打开即读

### 5.2 攻击可行性

| 事实 | 含义 |
|---|---|
| 程序无还原入口（12 个隐藏参数探测全部拒绝）| 还原能力完全寄生于钥匙 JSON——拿到钥匙=拿到还原能力 |
| 变换 = f(明文, 钥匙)，无隐藏随机量 | 逆变换存在且确定，一旦得知轮复合规则即可批量解密 |
| 轮复合规则是**全局唯一**的程序属性 | 规则被破解一次，**所有**历史/未来密文（配钥匙）均可解 |

### 5.3 算法完全逆向（未读源码，纯黑盒达成）

第二轮复合规则被完整破译，**通用解密器已建成并通过盲测**：

```
每轮变换 (共 rounds 轮):
  1. 跨步读组:   组 j = 位置 {j, j+g, j+2g, ...}   (g 个组, 每组 gs=n/g 字节)
  2. 组重排:     新组 j ← 旧组 sigma[j]
  3. 转置写回:   组内容连续排列 (跨步→连续 = 矩阵转置)
  4. 组内仿射:   组 j 内 new[m] = old[(a[j] + q[j]·m) mod gs]   (gather 方向)
```

- 轮复合语义由 **g=1 测试床**定案（643 为质数时工具被迫选 g=1，变换退化为纯仿射复合，46/46 锚点 + 4 个全排列质数样本验证 `gather_fixed`）
- 组挂载方式由 **g8_13（sigma=恒等）循环结构反推单轮映射 R** 后锁定（转置+仿射）
- 关键方法论教训：π 的 scatter/gather 方向两次搞反导致假阴性，最终以 `P[G[m]] = C[m]` 散射重建定案

### 5.4 通用解密器验证结果

| 验证项 | 结果 |
|---|---|
| 历史样本批量还原（33 例：n=8/12/15/24/101/103/107/109/115/643，9~24 轮）| **33/33 ✓** |
| 盲测（解密器写成之后才生成的新密文）| **✓ 完整还原** |
| 源码依赖 | **零**（仅凭 .gcop + .key + 40 行解密器）|

### 5.5 破译难度终审（密钥泄露后）

**分钟级，且已被实际完成**。攻击路径：拿到 .key（明文 JSON）→ 黑盒推断轮结构（本次耗约 2 小时、排除 8000+ 模板；有源码则分钟级）→ 通用解密 → 任意历史/未来密文批量还原。与"仅密文被劫持（2^5077 不可行）"形成两极。

**根本症结**：钥匙 = 明文 JSON 存储全部变换参数 + 算法随 .py 分发（Kerckhoffs 意义上算法公开）→ 唯一秘密就是钥匙文件本身，而它毫无保护。

### 5.5 建议

1. `.key` 绝不与 `.gcop` 同渠道分发（唯一命门）
2. 钥匙 JSON 建议至少做一层口令加密，避免直接暴露完整配方
3. 若需防篡改与真正的机密性，建议切换标准加密（AES-GCM/Fernet + 口令），混淆定位仅用于防 casual 阅读
4. 遵循 Kerckhoffs 原则评估：算法随 .py 公开，一切安全押在钥匙上——当前钥匙熵量（n=115 时约 170+ bit）合格，但前提是保管到位

## 六、无钥匙破译实测（算法逆向后的修正结论）

算法完全逆向后重新审视"只有密文、没有钥匙"的场景——**结论需要修正：存在可无钥匙破译的特殊情况**。

### 6.1 质数长度文件：秒级可破（已现场验证）

n=643（质数）时工具被迫选 g=1 → 整个变换退化为**纯仿射密码** `S(x) = α·x + β (mod n)` → 候选仅 n×φ(n) ≈ 41.3 万个。

实测：对 sample_test.txt.gcop **全程未使用钥匙**，暴力枚举 41.3 万候选（早停加速），α=135 唯一锁定，内容 **100% 还原**（命中解构成同一明文的循环旋转等价类，精确 β 存在，信息零损失）。

方法论细节：必须过滤 gcd(α, n) > 1 的候选——非互素 α 产生周期性退化序列（实测 α=52 生成"脉"字×52 的合法 UTF-8 假阳性）。

### 6.2 极短文件：可破译

n ≤ ~16 时参数空间（sigma! × a^g × coprime^g × rounds）仅 2^13~2^30，全枚举秒级。

### 6.3 常规合数长度文件：不可破译（cs.txt 现场实测）

现场挑战：cs.txt（156 = 2²×3×13 字节，合数）。纪律：未读明文、未读钥匙。

| 步骤 | 结果 |
|---|---|
| 元数据分析 | 全中文（无可打印 ASCII）、无换行、约 50 字量级（内容类型泄露，内容安全）|
| g=1 仿射假设（互素 α 过滤，7488 候选）| **零命中，干净排除** |
| g=2/g=3（参数空间 2^27/2^37）| 理论可行，但 25 个历史样本中 gs 恒在 2~23，工具未选过 |
| 最可能 g∈{12,13}（gs=13/12）| **参数空间 2^109~2^120，不可行** |

结论：该文件无钥匙不可破译。

### 6.4 无钥匙场景终审

| 文件长度 | 无钥匙破译难度 |
|---|---|
| **质数长度**（g=1 强制）| **秒级可破**（仿射退化，已实测）|
| **极短**（≤16B）| 秒~分钟级（参数全枚举）|
| **合数长度、常规大小** | 不可行（≥2^48，典型 2^109+）|

**修复建议**：将文件**填充至合数长度**（确保存在 2 ≤ gs ≤ 32 范围的真因子，如补齐到 4 的倍数），避开质数长度的仿射退化，无钥匙安全性即恢复到 2^100+ 水平。

## 七、总结论

**评级：作为文本混淆器，质量优秀。** 常规使用下（合数长度 + 钥匙保密）置换达到统计意义上的均匀随机，无钥逆向在计算上不可行，远超一般"字符打乱"类工具。

注意事项：
1. 这是**混淆不是加密**——安全性完全依赖 .key 的保密。分发时务必与密文分离渠道
2. **避开质数长度文件**（g=1 仿射退化，无钥匙可破）；建议填充至 4 的倍数
3. 若需防篡改，需外加 HMAC/签名
4. 内容类型/长度/行数等元数据必然泄露（直方图保留），如需隐藏可先压缩再混淆
5. 随机源已由作者确认为完全随机（CSPRNG 疑虑排除）

## 附：测试中自我纠正的统计假象与方法论记录

第一阶段（均匀随机性检验）：
1. "标记顺序 100% 保持" → 假象：位置排序后配对必然单调，无信息量
2. "位移呈平滑斜线" → 恰是均匀随机置换的理论期望 E[q(i)−i]=(n−1)/2−i
3. "36.6% 邻接对存活" → 重复 bigram（双空格×63 等）膨胀效应，零分布均值即 229

第三阶段（算法逆向）：
4. 标记单调性/排序配对假象同样污染了轮结构搜索——改用全异字节法直接取完整 π
5. π 的 scatter/gather 方向两次搞反导致假阴性（验证式须为 P[G[m]] = C[m]），纠正后 96 变体网格立即命中
6. 无钥匙仿射枚举须过滤 gcd(α,n)>1：非互素 α 产生周期退化假阳性（α=52 → "脉"×52）
